Exchange Online: Der endgültige Migrationsguide von EWS zur Graph API

Andy Schuon · 23. Februar 2026 · 10 Min. Lesezeit · 3 Kommentare

Microsoft hat die Abschaltung der Exchange Web Services (EWS) API für Mai 2027 endgültig bestätigt. Für IT-Administratoren bedeutet dies: Jetzt besteht dringender Handlungsbedarf, alle EWS-abhängigen Systeme auf die Microsoft Graph API umzustellen.

Hintergrund: Warum EWS abgeschaltet wird

EWS wurde ursprünglich als SOAP-basiertes Protokoll für Exchange Server 2007 eingeführt und war lange die Standardschnittstelle für Drittanbieter-Integrationen. Mit der zunehmenden Cloud-Fokussierung von Microsoft und der Einführung der modernen Graph API verliert EWS jedoch an Bedeutung.

Welche Systeme sind betroffen?

Folgende Anwendungstypen nutzen typischerweise EWS und müssen migriert werden:

  • Backup-Lösungen mit Postfach-Zugriff (z.B. Veeam, ArcServe)
  • CRM-Systeme mit Outlook-Synchronisation
  • Legacy PowerShell-Skripte mit EWSManagedAPI
  • Kalender- und Raumbuchungssysteme
  • Drittanbieter E-Mail-Archivierungslösungen

Die Migration zur Graph API

Die gute Nachricht: Die Graph API bietet für nahezu alle EWS-Funktionen eine moderne Entsprechung. Das folgende Skript zeigt exemplarisch, wie ein Postfach-Zugriff mit dem Graph PowerShell SDK realisiert wird:

# EWS → Graph API Migration
# Verbindung mit Microsoft Graph
Connect-MgGraph -Scopes "Mail.Read","Calendars.Read"

# Alle Postfächer eines Benutzers abfragen
$messages = Get-MgUserMessage -UserId "admin@contoso.com" `
    -Filter "isRead eq false" `
    -Select "subject,from,receivedDateTime" `
    -Top 50

$messages | Select-Object Subject, ReceivedDateTime

App-Permissions konfigurieren

Für den automatisierten Zugriff ohne Benutzerinteraktion (Daemon-Apps, Skripte) sind Application Permissions erforderlich. Diese müssen von einem Global Administrator in Entra ID genehmigt werden.

Tipp: Verwenden Sie das Prinzip der minimalen Rechtevergabe (Least Privilege). Nicht jede App benötigt Mail.ReadWrite – oft reicht Mail.Read vollständig aus.

Migrations-Checkliste

Gehen Sie diese Punkte systematisch durch, bevor Sie EWS-Verbindungen deaktivieren:

  1. Inventarisierung aller EWS-nutzenden Anwendungen mit Get-EWSUsage.ps1
  2. App-Registrierung in Entra ID für jede Anwendung anlegen
  3. Graph API Permissions gemäß Least-Privilege-Prinzip zuweisen
  4. Parallelbetrieb testen (EWS + Graph gleichzeitig aktiv)
  5. Monitoring einrichten: Graph API Fehlerrate überwachen
  6. EWS schrittweise deaktivieren, beginnend mit nicht-kritischen Systemen
